# h0 Compile and Analyze

## Tavoite

Tehtävänä oli tehdä yksinkertainen ohjelma, kääntää se ja tutkia syntynyttä binääritiedostoa. 

## Ohjelman tekeminen

Tein C-kielellä yksinkertaisen ohjelman, joka tulostaa tekstin Hello World.

Ohjelman koodi:

```c
#include <stdio.h>

int main() {
    printf("Hello World");
    return 0;
}
```

## Käänsin ohjelman komennolla:

gcc hello.c -o hello

## Sen jälkeen suoritin ohjelman:

./hello

## Ohjelma toimi ja tulosti:

Hello World

## Binääritiedoston tutkiminen

Ensin tarkistin, millainen tiedosto ohjelmasta syntyi:

file hello

Tuloksesta näkee, että kyseessä on ELF64-tiedostoю Tiedosto on dynamically linked.

## ELF header

Seuraavaksi tutkin ELF-headeria komennolla:

readelf -h hello

Tuloksesta näkee esimerkiksi, että tiedosto on 64-bittinen ja käyttää little endian -muotoa. Machine-kohdassa näkyy Advanced Micro Devices X86-64. Entry point address on 0x1050.

Symbolit ja sectionit

Tutkin myös binääritiedoston symboleita ja sectioneita readelf-komennolla.

Tuloksissa näkyy esimerkiksi main, printf, .text, .data, .bss ja .rodata.

## Strings

## Käytin komentoa:

strings hello

Tuloksessa näkyy ohjelmassa käytettyjä tekstijonoja. Siellä näkyy esimerkiksi Hello World sekä tietoja GCC:stä ja GLIBC:stä.

Disassembly

## Seuraavaksi tutkin ohjelman konekoodia:

objdump -d hello

Etsin tuloksesta main-funktion. Siellä näkyy esimerkiksi printf-funktion kutsu. Funktion lopussa näkyy ret.

.rodata

Lopuksi tutkin .rodata-sectionin:

readelf -x .rodata hello

## Yhteenveto

Tein yksinkertaisen C-ohjelman ja käänsin sen GCC:llä. Sen jälkeen tutkin syntynyttä ELF-binaaritiedostoa eri komennoilla. file-komennolla sain perustietoja tiedostosta, readelf-komennolla tutkin ELF-rakennetta, strings-komennolla löysin binääristä tekstijonoja ja objdump-komennolla tutkin ohjelman konekoodia.
